# ADR-0029 — Block page names the domain; popup blocklist label matches its sibling

- **Date:** 2026-09-08
- **Status:** Accepted (already shipped)
- **Context:** The block interstitial (`extension/blocked.html`) redirected the tab but never rendered *what* it blocked — a user landing there without having just typed the URL (stale tab, bookmark, link click) had no on-screen confirmation. Separately, the popup's blocklist chip group showed a live count (`blocking 4`) while its sibling work-sites group used a plain label (`where it happens`) — two label grammars for two structurally identical groups, and a third shape again on the running screen's joined-list summary.
- **Decision:** The block page's existing lowest-emphasis line (`.m-row-figure`) now reads `${domain} — ${remainingOrElapsedText}` instead of the time alone — no new element, no new color, no new class, domain folded into the existing muted register rather than promoted to a heading (naming the temptation is not the page's job). The popup's idle-state blocklist header becomes the static string `what to block`, matching `where it happens` in tense and the absence of a count; the running-screen's joined-list summary is left as-is (a status readout, not an input-group header — no inconsistency was found there).
- **Consequences:** Both fixes reuse existing classes/tokens only — zero new visual language. The running-state list and the two design canvas artboards (`BlockPage.dc.html`, `PopupIdle.dc.html`) are now known, flagged deviations from the artboards (the artboards only had to render one clean demo, not resolve a label-grammar or a missing-referent), not silently-diverging bugs.
