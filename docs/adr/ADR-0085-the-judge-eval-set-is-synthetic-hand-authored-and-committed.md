# ADR-0085 — The judge's eval set is synthetic, hand-authored, and committed

- **Date:** 2026-09-25
- **Status:** Accepted
- **Supersedes:** one clause of ADR-0073, *"the answer key is produced by hand, from real recorded sessions"*. Only the words "from real recorded sessions". The rest of ADR-0073 stands: a verdict is inference, it is gated by measured precision on a held-out, labelled set plus a per-verdict confidence floor, the split is by session, and the comparison is against what the product gets right with no model.
- **Context:** ADR-0073's real-session answer key can't be built. The 30-day on-device TTL (`PATH_TTL_MS`, ADR-0059) purged the paths, only 7 real sessions still have them, and the owner will not dogfood more. ADR-0073 already named the cost of real paths: they can't be committed (ADR-0059), so nobody without the owner's fixture could re-run the eval. This is a reference product for a course, so an eval students can't re-run teaches nothing. ADR-0073 called a synthetic set "the long-term fix", out of scope then. The owner brought it into scope on 2026-09-25.

  The judge spike (`docs/superpowers/specs/2026-09-21-judge-spike-findings.md`) was also synthetic, and its main weakness was that one generator wrote the data and the labels together, from templates. Nothing in its answer key was independent of the data.
- **Decision:** **The judge's eval set is a synthetic, hand-authored file, `eval/judge-cases.json`, committed to the repository. Every path in it is fictional.**

  - **Who labels it.** An AI agent authors the labels at the owner's instruction. They are not the work of a blind human, and nothing below should be read as if they were. The one safeguard: the sessions are written first, with no labels, and a separate agent context labels them afterwards. That agent sees only what a human labeller would see (intention, hour, outcome, declared sites, hosts, paths, dwell) and never sees the author's intent. Both passes run on the same model family, so the labels are independent of the author's intent but not of the model's own habits.
  - **Vocabulary.** ADR-0076's four labels (`focused`, `supportive`, `neutral`, `drift`), plus `unknown` for a visit where the record genuinely does not show which it was. Each label carries a one-line reason. The judge's schema cannot emit `unknown`. The judge gets an `unknown` row right by staying below the floor, which is ADR-0037.
  - **Size, answering PRD Q10 for now:** about 40 sessions and at least 200 visits, split 50/50 **by session** with the spike's deterministic `splitBySession`. That leaves about 100 visits per side. **A precision figure resting on fewer than 20 rendered verdicts is not a measurement:** at n = 20, a measured 0.80 has a 95% interval of roughly ±0.18. Q10 is answered only for a course reference product. A version sold to users needs a larger, consented set.
  - **Pass criteria, fixed here before any data is written or any model is run.** On the held-out **test** split, **both** of these must hold:
    - **(a) Accuracy over all rows.** The judge's accuracy over **every** labelled test visit must beat the no-model baseline's. The judge's prediction for a visit is its label when confidence ≥ the floor, and `unknown` otherwise. A visit with no prediction at all counts as **wrong**: a session truncated by rate limits or errors after retries, or a host missing from the response. The baseline is the declaration alone (ADR-0035): a declared work site is `focused`, a declared distraction is `drift`, and every undeclared host gets one constant. Both constants are computed on test, `neutral` (the spike's rule) and `unknown` (the product's real behaviour, which says nothing), and **the judge must beat the stronger of the two**. A tie fails.
    - **(b) Precision among rendered verdicts.** Precision must be **≥ 0.80** among rendered test verdicts, meaning confidence ≥ the floor, on at least 20 of them. A rendered verdict on a visit labelled `unknown` is wrong.
  - **The floor** is the lowest confidence on the grid 0.00, 0.05, …, 0.95 at which **dev**-split precision among rendered verdicts is ≥ 0.80 on at least 20 rendered verdicts. It is set from dev alone, before test is ever run. If no grid point qualifies, the gate fails and test is not run.
  - **Order, recorded as committed files under `eval/results/`:** the set itself, then the baseline on test, then the judge on dev, then the floor, then the judge **once** on test. The judge runs through the same prompt and schema builders and the same request as the production route (`lib/judge/*`, `openai/gpt-oss-120b` via Groq, ADR-0080). **No change to the set, the criteria, the prompt, or the floor after test results are seen.** If the test run fails, the failure is the result.
- **Consequences:**
  - Anyone with a Groq key can re-run the eval with `npm run eval:judge`. That is the property ADR-0073 had to give up, and the reason for this decision.
  - **What a pass would and would not license.** A pass on this set shows the judge beats the declaration on cases written to be the product's defining ones: Instagram as work against Instagram as drift, undeclared residual sites, in-site ambiguity, and visits the record can't resolve. It does not show the judge works on real browsing, which is messier than anything written to be representative. The limit belongs to the set, and every result that cites it inherits it.
  - A later real or consented set does not edit this file. It gets its own ADR and its own result.
  - **Accepted, not overlooked:** the labeller and the author are the same model family, and the judge is a different one (`gpt-oss`). A judge that shares the labeller's biases would score better than it deserves. That is one reason a different family judges this set.
