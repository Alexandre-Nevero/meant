# ADR-0032 — Round 5: local attention tally, the pill as a segmented perimeter loop, merged duration/cycle picker

- **Date:** 2026-09-09
- **Status:** Accepted (already shipped)
- **Context:** Three unfinished threads converged: (1) the running popup had no live per-site attention data at all (`session.tally` was initialized but never written or read — a reserved-but-unbuilt slot from an earlier plan); (2) the timer pill's progress signal was a single 3px strip on its bottom edge only, when feedback wanted the full perimeter carrying the same segmented-band language used elsewhere in the product; (3) the duration picker and the cycle picker were two separate, disagreeing controls (different defaults, overlapping meaning).
- **Options considered (item 1, live data source):** a polled `/api/sessions/:id/review` endpoint with an offline fallback (proposed) vs. a local `chrome.storage.local` tally with no network. The local tally was chosen and the polling design dropped entirely — polling would introduce a network dependency into the most-opened surface in the product, need a staleness UI, and violate the product's own "nothing waits on a model, ever" constraint; the tally is one pure module plus ~4 lines in `transition()`.
- **Decision:**
  - `extension/lib/tally.js` (new): pure functions `withOpenSlice` (tops up the tally with the currently-open slice at read time) and `toSegments` (top-3 domains by seconds + away, same `{kind, flex}` shape the review's `lib/band.ts#toBand` produces).
  - The pill's outline becomes an authored SVG `<path>` (a rounded-rect traced from true top-dead-centre, clockwise) with `stroke-dasharray`/`stroke-dashoffset` per segment — not a CSS border (confirmed `border-image` + `border-radius` doesn't combine reliably cross-browser) and not the old bottom-edge strip. Uniform 2px stroke (up from 1.5px) because the third clay tint is otherwise invisible at the old weight. A 5% floor (`MIN_ARC`) guarantees the first segment is never invisible on a cold start. The remainder segment is now solid, not dashed (the dashed hairline read as "unstyled/loading," not as the review band's dashed *rectangle* convention it was modeled on — different objects, and `remainder` has zero live producers on any band today). Away and break time fold into the remainder on the loop itself (an SVG stroke can't render the product's hatch pattern at 2px) — the full away-as-hatch vocabulary stays on the outcome screen's 14px band, which is new in this round (item F) and reuses `.m-row-bar[data-kind]` with no new CSS.
  - The picker collapses to one always-visible single-select (`25/5` / `50/10` / `custom`) plus a reveal-on-`custom` second level (labelled work/break inputs, `until I stop` / `no cycles`) — replacing two separately-defaulted controls with one state model where a cycle's length *is* the session's planned duration, with `until I stop` as the one named unbounded escape hatch. Default resolved with the product owner: `mode: '25/5'`. A prior capability — a bounded, countable number of repeated cycles inside one planned session — is explicitly retired; `until I stop` is now the only way to repeat a cycle, and it's unbounded.
  - Everything above stays fully static, recomputed only on the popup's own natural re-render (`document.fonts.ready` + one `requestAnimationFrame`) — no `setInterval`, no live tick, matching the product's explicit refusal of a ticking countdown or progress dial.
- **Consequences:** Two design canvas artboards (`PopupRunning.dc.html`, `PopupIdle.dc.html`) were confirmed stale against this round and were redrawn as part of the same work, not left disagreeing. The web app's review/dashboard pages, `lib/band.ts`, and `extension/companion-overlay.js` were explicitly out of scope and untouched.
